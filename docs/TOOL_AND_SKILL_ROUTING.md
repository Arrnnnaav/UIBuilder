# Tool, skill and hook routing (2026-09-28)

This is the harness's routing map, not proof that a third-party product is installed or connected. The exact current role/tool/domain counts are generated by `node scripts/validate-brain.mjs` and `node scripts/validate-contracts.mjs`; do not rely on old fixed counts here. Claude/Codex global plugins and hooks belong to the local user environment and are not project-owned guarantees.

Fresh agents use [`AGENT_BOOTSTRAP.md`](AGENT_BOOTSTRAP.md) and `node scripts/agent-bootstrap.mjs` to check task-relevant skills/tools against the pinned, license-reviewed [`brain/agent-bootstrap.json`](../brain/agent-bootstrap.json). This catalog standardizes setup; `brain/tools.json` still controls whether an agent can use a tool in a given task. Installation does not configure plugins, hooks, credentials or remote integrations.

## Choosing a tool

The Orchestrator starts from the current stage and responsible agent in `brain/domains.json`. The agent reads the site's brief, owner taste, locked design and current state. `scripts/recommend-resources.mjs` ranks matching resources while separating ready entries from trust, rights or availability review. The tool router checks that the agent may use the tool and its `enabled_if` condition holds. An unavailable tool uses its recorded fallback; no website screenshot or model suggestion overrides the file contract or owner gates.

## Jev's place

Jev handles narrow semantic judgments over public text and returns typed probabilities. The adapter currently supports advisory task routing and internal-link relevance. It has a live key in an ignored root `.env`, a six-case synthetic smoke test, and no authority to dispatch, edit SEO, approve rights, waive tests or deploy. See [Jev research](JEV_RESEARCH.md). The official TypeSafe skill is loaded for implementation guidance; live docs remain the source of truth.

## Security and code-review tool status

The default quality controls are deterministic project checks (typecheck, lint, tests, build, Playwright, accessibility/performance/SEO checks as configured), the `security_review_skill` procedure and the project's package-manager dependency audit. The harness CI and future-site starter CI additionally have two free, tokenless scanner jobs: Semgrep Community Edition engine with original UIBuilder Apache-2.0 rules, and Gitleaks CLI for secrets/history. Both use images pinned by digest; neither uses an LLM/API token. Semgrep-maintained rules carry separate terms limited to internal business use, so they are deliberately excluded from client-capable pipelines. Gitleaks was run locally against the harness: 52 commits, about 5.97 MB, zero leaks. The original Semgrep rules still need local/CI execution verification. Other third-party products below remain optional routes, not installations. No secrets, paid integrations, or credentials are added to CI.

| Tool | Harness status | Intended place / constraint |
|---|---|---|
| CodeRabbit | Optional hosted PR review; not configured | PR review only. Verify current plan and source handling, especially for private repos. |
| PR-Agent | Optional self-hosted AI reviewer; not installed | PR diffs; model/provider costs and source disclosure apply. Community-maintained project. |
| Kodus | Optional self-hosted AI reviewer; not installed | PR diffs; core AGPL-3.0 and some enterprise paths separately licensed. Review exact files/license before adopting. |
| Semgrep CE | Configured in root and future-site CI using pinned Docker image; no model calls | Uses original rules from `security/semgrep/` (Apache-2.0); Semgrep-maintained rule packs are not used. Scan verification pending. |
| CodeQL | Optional; not enabled | Semantic source analysis. Private GitHub scanning can require paid GitHub Code Security; check repo visibility and plan. |
| SonarQube | Optional local/server analysis; not installed | Maintainability/security quality; server and edition/resource requirements must be checked. |
| OSV-Scanner | Optional local dependency scanner; not installed | Known dependency vulnerabilities; do not auto-run remediation scripts. |
| Gitleaks CLI | Configured in root and future-site CI using pinned official Docker image; locally verified | Full history scan with redacted output. Rotate any exposed credential; removing its file is not enough. |
| TruffleHog | Optional local secret/history scan; not installed | Prefer local-only mode; never verify credentials against external services without explicit approval. |
| Nuclei | Optional DAST CLI; not installed | Explicitly authorized local/staging URL and narrow templates only. |
| Strix | Optional AI pentest; not installed | Owner-authorized local/staging code or target only; Docker/model/provider costs and outbound data must be reviewed. |

The distinctions matter: PR reviewers inspect changes; SAST analyzes source; dependency/secrets scanners inspect packages or credentials; Nuclei/Strix probe a running target. The router gives these to `production-auditor` and `ship` only as optional capabilities. It never grants a scanner permission to deploy, change policy, waive a gate or attack an unapproved target. Primary references: [Semgrep Community Edition](https://semgrep.dev/products/community-edition/), [Semgrep Rules License](https://semgrep.dev/legal/rules-license/), [Gitleaks CLI](https://github.com/gitleaks/gitleaks), [PR-Agent](https://github.com/The-PR-Agent/pr-agent), [Kodus license](https://github.com/kodustech/kodus-ai/blob/main/license.md), [Strix open-source setup](https://www.strix.ai/open-source-pentesting), [GitHub CodeQL private-repo requirements](https://docs.github.com/en/code-security/reference/code-scanning/troubleshoot-analysis-errors/private-repository-enablement).

## Add a new resource safely

`/intake <url>` verifies the primary source, license and maintainer state, assigns `usage_mode`, `best_for`, trust and provenance, and records mechanisms without copying assets. NEW/REVIEWED candidates are visible in the selector's review queue. A real project use with tests and owner feedback can advance trust. `/learn` records whether the pattern worked; failed or restricted resources can be rejected/deprecated. Adding a tool to the router does not install or enable paid infrastructure.
