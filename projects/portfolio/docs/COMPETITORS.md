# COMPETITORS — portfolio (peer-portfolio note only)

This is a personal portfolio, so it has no client site and no commercial competitors. Per the S2 brief, this file is a short note. The peers are other early-career backend/AI engineers competing for the same recruiter attention.

- **The typical peer pattern (to differ from):** a gradient hero with a headshot, skill bars or a logo wall, and project cards reading "Built X with Y" with no outcome. `brain/preferences.md` → Avoid already rules this out.
- **What recruiters scan for:** roundups repeat the same guidance.
  - Recruiters skim for about 8 seconds.
  - The top 3 projects should show role and stack without scrolling.
  - Outcomes should be quantified, e.g. "cut p95 from 800ms to 120ms".
  - Repo and demo links must work.

  Sources: [sitesplaced.com](https://sitesplaced.com/best-portfolio-website-for-software-engineers), [sitebuilderreport.com](https://www.sitebuilderreport.com/inspiration/software-engineer-portfolios).
- **What the peers rarely do, and the owner can:** show *how* a number was measured (n, method, conditions), as engineering benchmark pages do. See `planetscale-benchmarks` and `samwho-dev` in REFERENCE_BREAKDOWN.md.
- **Open:** once the owner shares the names of engineers they admire, a peer pass can open 3–5 real portfolios.
